# 🧩 FlexSoC IP development guide

This is the **step-by-step engineering guide** for developing and qualifying one reusable IP with FlexSoC.

It assumes the FlexSoC environment is already available. Installation and environment setup belong to the top-level [README](../README.md), not to IP development itself.

For the narrative project evolution, see [Project lifecycle](project_lifecycle.md). For exact command syntax and variables, see [Command reference](command_reference.md). For backend/repository internals, see [Architecture](architecture.md).

> **Working rule:** authored intent is edited; generated setup is regenerated explicitly; execution consumes existing validated setup.

---

## 1. Understand the run and ownership model

One run lives under:

```text
<WORKDIR>/runs/<RUN_TOP>/<RUN_ID>/
```

The current PDK adds technology-scoped branches without duplicating the common design:

```text
runs/<RUN_TOP>/<RUN_ID>/
├── data/                         CSR/HJSON inputs
├── rtl/                          core/top/filelists
├── doc/                          generated register docs
├── constraints/<TOP>.sdc         authored timing contract
├── dv/
│   ├── functional/
│   └── formal/
├── analysis/cdc_rdc/             technology-independent crossing analysis
├── syn/<pdk>/                    mapped synthesis branch
├── impl/<pdk>/                   physical implementation branch
├── signoff/<pdk>/                technology sign-off
├── logs/
└── meta/
    ├── design_intent.json
    └── <pdk>/
        ├── settings.json
        ├── provenance.json
        ├── manifest.json
        └── metrics.json
```

### 1.1 Authored sources

Normally preserve and review these rather than blindly regenerating them:

```text
data/<top>*.hjson
rtl/<top>_core.sv
constraints/<TOP>.sdc
dv/functional/model/<top>_model.py
dv/functional/model/<top>_tests.py
dv/formal/properties/
```

### 1.2 Generated boundaries

These are machine-owned and should be recreated from their inputs when stale:

```text
register RTL/docs/regmap
generated top wrapper
ordered filelists
functional vectors/testbench setup
formal setup
CDC/RDC extraction setup
synthesis/EQY/sign-off/PnR setup
metrics and manifest snapshots
```

A run target does not regenerate its setup implicitly. The normal pattern is:

```bash
fx syn --setup
fx syn
```

not “run synthesis and hope it rewrites setup for me”.

## 2. Configure the run

Set a stable run identity first.

### 2.1 Single clock

```bash
fx settings \
  TOP=my_ip RUN_TOP=my_ip RUN_ID=dev HOST=uart \
  N_CLOCKS=1 \
  CLOCK_DOMAINS=core:clk_i:rst_ni:10:low \
  CLOCK_RELATIONSHIPS=
```

### 2.2 Multiple clocks

```bash
fx settings \
  TOP=tri_stream_dsp RUN_TOP=tri_stream_dsp RUN_ID=dev HOST=uart \
  N_CLOCKS=3 \
  'CLOCK_DOMAINS=cfg:cfg_clk_i:cfg_rst_ni:20:low,rx:rx_clk_i:rx_rst_ni:16:low,dsp:dsp_clk_i:dsp_rst_ni:30:low' \
  'CLOCK_RELATIONSHIPS=async:cfg:rx,async:cfg:dsp,async:rx:dsp'
```

`CLOCK_DOMAINS` owns bootstrap domain/reset topology. `CLOCK_RELATIONSHIPS` initializes the first SDC relationship intent. Once `constraints/<TOP>.sdc` exists, timing values and relationships are authored in the SDC.

For N clocks, each domain should have a reset association that can be synchronized relative to that domain. `top_from_core` inserts the reset release synchronization directly with `prim_ff_2sync`; no wrapper-only reset primitive is introduced.

## 3. Create the run and design-entry scaffold

```bash
fx setup --force
fx hjson --force
fx reg doc --force
fx rtl_stub --force
fx top_from_core --force
fx flist --force
```

Then edit the real sources of truth:

```text
data/<top>.hjson
rtl/<top>_core.sv
```

Use generated register RTL and documentation as derivatives of HJSON, not as independent design sources.

If the core interface changes, regenerate:

```bash
fx top_from_core flist --force
```

### 3.1 Reset integration generated by `top_from_core`

For a single clock, the generated wrapper creates one synchronized reset release:

```text
rst_ni
  ↓ asynchronous assertion
prim_ff_2sync
  ↓ synchronous release on clk_i
core_rst_sync_ni
  ↓
core + generated register block
```

For multiple domains, FlexSoC emits one equivalent `prim_ff_2sync` instance per domain/reset pair. The external asynchronous reset should not fan out directly to every functional register after the wrapper has established a domain-local synchronized release.

---

## 4. Close lint before timing-aware analysis

Run both supported lint views:

```bash
fx lint_suite
```

Do not continue because a later tool happens to accept malformed or ambiguous RTL. Fix:

- parse/elaboration failures;
- width mismatches;
- accidental latches;
- unused/unconnected signals that indicate real integration mistakes;
- incorrect generated-top/filelist boundaries.

If lint fails, inspect the lint logs and fix the owning RTL/HJSON/generator input. Do not patch synthesized or sign-off artifacts.

---

## 5. Create and author the timing contract

Only after the RTL hierarchy is structurally clean, initialize the SDC:

```bash
fx sdc --setup --force
```

The canonical file is:

```text
constraints/<TOP>.sdc
```

Review it before continuing. It is designer-owned timing intent and should contain the real design assumptions:

- primary/generated clocks;
- waveform/duty cycle;
- source latency;
- setup/hold uncertainty;
- clock transition;
- synchronous/asynchronous clock relationships;
- input/output delays;
- input drive or driving cell;
- output load;
- deliberately reviewed timing exceptions;
- optional design-rule limits.

False paths and multicycle paths are never inferred automatically.

### 5.1 Synthesis uses the authored SDC

`syn --setup` reads the I/O environment from this SDC. In particular, output load is converted from the selected Liberty capacitance unit into the femtofarad value required by Yosys/ABC. Editing `set_load` and regenerating synthesis setup must therefore change `abc.constr`; there is no synthesis-side hardcoded load fallback.

`set_driving_cell` can be propagated to ABC when authored. A numeric SDC `set_drive` remains useful to STA but is not fabricated into an arbitrary standard-cell choice.

### 5.2 Clock stimulus uses the same intent

Functional SV and cocotb derive digital clock behavior from the active SDC subset:

```text
create_clock -period/-waveform
set_clock_latency -source
set_clock_uncertainty -setup/-hold
```

The SDC is therefore shared intent, not a sign-off-only file.

## 6. Run CDC/RDC after lint and SDC

Generate the extraction setup first:

```bash
fx cdc_rdc --setup --force
fx cdc_rdc
```

The order matters:

```text
RTL/top/filelist
→ lint
→ constraints/<TOP>.sdc
→ cdc_rdc --setup
→ cdc_rdc
```

`cdc_rdc` is run-only and refuses to execute when `cdc_rdc --setup` provenance is missing, stale, modified, or invalid.

### 6.1 Canonical CDC/RDC artifacts

FlexSoC deliberately keeps this analysis compact:

```text
analysis/cdc_rdc/
├── extract.ys
├── design.json
├── summary.json
└── cdc_rdc.rpt

logs/analysis/cdc_rdc/
└── extract.log
```

Meaning:

- `design.json`: raw Yosys structural evidence;
- `summary.json`: complete machine-readable classifications, findings, setup/glitch checks, reset checks, and verification obligations;
- `cdc_rdc.rpt`: human report;
- `extract.ys` + `extract.log`: reproducible extraction setup and raw execution evidence.

Do not add one JSON file per checker unless a real consumer requires it.

### 6.2 What to review

Review:

- scalar and multi-bit clock crossings;
- FIFO/Gray/handshake candidates;
- reconvergence;
- reset-domain crossings;
- reset synchronizers;
- asynchronous reset release;
- reset sequencing;
- setup/glitch findings.

A direct asynchronous reset release into many functional registers is a design problem. The generated top reset synchronization should reduce raw recovery/removal exposure to the synchronizer itself.

---

## 7. Build functional verification

Create the model workspace once:

```bash
fx model --setup --force
```

Then author:

```text
dv/functional/model/<top>_model.py
dv/functional/model/<top>_tests.py
```

Generate scenario vectors and simulator setup:

```bash
fx tests_gen --force
fx tb cocotb --setup --force
```

Run the regression and coverage:

```bash
fx regression
fx coverage_detail
```

Use the model and scenarios as the behavioral source of truth. Do not encode expected values independently in multiple simulator-specific testbenches.

For waveform inspection:

```bash
fx view
fx view_cocotb
```

When CSR HJSON changes but the model workspace is already authored, prefer regenerating only the CSR API/vector derivatives rather than recreating the whole model directory.

---

## 8. Build formal verification

Generate the formal setup explicitly:

```bash
fx formal --setup --force
fx formal_csr --setup --force
fx formal_prove formal_cover --setup --force
```

Run:

```bash
fx formal
```

The formal view combines:

- generated CSR semantic properties;
- authored design properties;
- explicit assumptions;
- BMC/prove/cover evidence.

A timeout is not a mismatch. Distinguish proof failure, solver error, timeout, and unresolved partitions in the retained evidence.

---

## 9. Select a PDK and synthesize

Select one technology branch:

```bash
fx pdk use sky130
```

or:

```bash
fx pdk use ihp-sg13g2
```

Then:

```bash
fx syn --setup --force
fx syn
```

The mapped netlist lives under:

```text
syn/<pdk>/<top>_synth.v
```

Changing PDK does not regenerate HJSON, RTL, model, tests, formal properties, or `constraints/<TOP>.sdc`.

---

## 10. Prove RTL-to-netlist equivalence

```bash
fx eqy --setup --force
fx eqy
```

For unresolved partitions:

```bash
fx eqy_debug
fx eqy_debug <partition>
fx eqy_debug --wave <partition>
fx eqy_debug --files <partition>
```

Equivalence is the behavioral gate between synthesis and downstream sign-off.

---

## 11. Run pre-layout sign-off

Generate common sign-off setup:

```bash
fx signoff --setup --force
```

Then run the core analyses:

```bash
fx sdf
fx sta
fx power_estimate
```

### 11.1 STA evidence

Canonical STA evidence:

```text
signoff/<pdk>/sta/sta.rpt
signoff/<pdk>/sta/sta.json
```

Scenario-local reports are detailed raw/diagnostic evidence. `sta.json` is the machine-readable analysis summary.

STA records:

- scenario corner and mode;
- WNS and TNS;
- violation count;
- real unconstrained endpoints;
- minimum period/Fmax where available;
- reset recovery/removal observations;
- electrical checks;
- routed/unrouted stage identity.

Pre-layout min/recovery/removal problems remain visible but do not substitute for post-route closure after CTS.

### 11.2 Filtered debug

Read existing artifacts without rerunning the analysis:

```bash
fx sta --debug
```

Save the filtered view:

```bash
fx sta --debug -o sta_debug.txt
```

`--debug` is for drill-down. It should show compact tabular QoR plus only the most relevant violations/near-critical evidence, not dump the complete raw report.

### 11.3 Post-synthesis GLS

Compile/run gate simulation as required:

```bash
fx compile_post_syn --force
fx sim_post_syn --force --set GLS_BACKEND=sv --set TIMING_MODE=typ
```

Qualification timing modes are:

```text
zero   no SDF delay
unit   unit-delay model
min    FF/min SDF
 typ   TT/typ SDF
max    SS/max SDF
```

For a complete matrix, use the `*_all` targets or separate deterministic runs rather than hiding multiple configurations inside one ambiguous result.

### 11.4 Activity power and fusion

For qualified GLS activity:

```bash
fx power_analysis_all
fx fusion_analysis_all
```

Keep vectorless power estimate and workload/activity power separate in metrics; they answer different questions.

---

## 12. Run physical implementation

Configure ORFS/OpenROAD:

```bash
fx pnr --setup --force --set ORS=/path/to/OpenROAD-flow-scripts/flow
fx pnr --force --set ORS=/path/to/OpenROAD-flow-scripts/flow
```

Open the implementation GUI when useful:

```bash
fx pnr_gui --set ORS=/path/to/OpenROAD-flow-scripts/flow
```

FlexSoC selects final ORFS artifacts from the canonical implementation branch instead of relying on arbitrary “latest file” globs.

---

## 13. Run post-PnR sign-off

Prepare the routed sign-off setup:

```bash
fx signoff_post_pnr --setup --force
```

Then:

```bash
fx sdf_post_pnr
fx sta_post_pnr
```

Normally the final netlist/SPEF are resolved from the canonical implementation branch. Use explicit `NETLIST`/`SPEF_FILE` overrides only for intentional exceptional analysis.

Run routed GLS and power/fusion qualification as required:

```bash
fx compile_post_pnr --force
fx sim_post_pnr_all --set GLS_BACKEND=sv --set TIMING_MODES=all --set TEST_NAMES=all --set SDF_STRICT=1
fx power_estimate_post_pnr
fx power_analysis_post_pnr_all
fx fusion_analysis_post_pnr_all
fx physical_signoff --set ORS=/path/to/OpenROAD-flow-scripts/flow
```

### 13.1 Why post-route STA is different

Post-route STA uses:

```text
final netlist + SPEF + propagated clock + authored <TOP>.sdc
```

A real hold/recovery/removal failure here is a closure problem. Unlike pre-layout min timing, it should not be globally downgraded simply to keep an E2E moving.

Use:

```bash
fx sta_post_pnr --debug
```

for filtered drill-down.

## 14. Capture release evidence

Generate identity first:

```bash
fx manifest
```

Collect the current normalized snapshot:

```bash
fx metrics
```

This writes:

```text
meta/<pdk>/metrics.json
```

`fx metrics` is a **collector**, not the human dashboard.

Render the saved snapshot:

```bash
fx check
```

`fx check` does not recollect metrics. It reads the exact saved `metrics.json` and renders the lifecycle in a colored, ordered, tabular view.

Therefore:

```text
flow changes after metrics
        ↓
old metrics.json remains a valid historical snapshot
        ↓
run fx metrics again to capture the new state
        ↓
fx check renders that new snapshot
```

This separation makes the JSON suitable for CI comparison and future graphical rendering.

### 14.1 Evidence hierarchy

Use the appropriate level:

```text
raw evidence
  tool logs, timing.rpt, power.rpt, SDF, SPEF, waves

analysis JSON
  sta.json, CDC/RDC summary.json, power/fusion/GLS summaries

metrics.json
  normalized cross-analysis snapshot

fx check
  human lifecycle dashboard
```

Do not make a GUI parse raw `.rpt` files when a normalized JSON layer already exists.

## 15. Load an existing reusable IP

Start an isolated run and load the package:

```bash
fx setup --force
fx ip_load --force --set IP_NAME=<name>
fx flist --force
```

The package-owned:

```text
constraints/<TOP>.sdc
```

is restored as authored timing intent. Do **not** call `fx sdc --setup --force` merely because the IP was loaded; that would overwrite/reinitialize the package timing contract.

Then qualify the loaded IP in the normal order:

```bash
fx lint_suite
fx cdc_rdc --setup --force
fx cdc_rdc
fx tests_gen --force
fx tb cocotb --setup --force
fx regression
fx coverage_detail
fx formal --setup --force
fx formal
```

Then select each required PDK and continue from synthesis onward.

---

## 16. Save a reusable IP

After qualification:

```bash
fx manifest
fx metrics
fx check
fx ip_save --set IP_NAME=<name> --set IP_LIBRARY_ROOT=<library>
```

If the package branch already exists and is intentionally being refreshed:

```bash
fx ip_save --force --set IP_NAME=<name> --set IP_LIBRARY_ROOT=<library>
```

`ip_save` is atomic and non-destructive by default. With `--force`, the current PDK/source-backed destinations are refreshed while unrelated PDK branches are preserved.

A multi-PDK package can therefore accumulate:

```text
<name>/
├── constraints/<TOP>.sdc
├── analysis/cdc_rdc/
├── syn/
│   ├── sky130/
│   └── ihp-sg13g2/
├── impl/
│   ├── sky130/
│   └── ihp-sg13g2/
├── signoff/
│   ├── sky130/
│   └── ihp-sg13g2/
└── meta/
    ├── design_intent.json
    ├── sky130/
    └── ihp-sg13g2/
```

The package intentionally retains compact canonical analysis evidence rather than every transient log/runtime Tcl copy.

For a newly authored IP:

```bash

fx hjson reg doc rtl_stub top_from_core flist --force

fx sdc --setup --force
# review constraints/<TOP>.sdc

fx cdc_rdc
fx model --setup --force
fx tests_gen --force
fx tb cocotb --setup --force
fx regression
fx coverage_detail
fx formal --setup --force
fx formal

# One technology branch
fx pdk use sky130
fx syn --setup --force
fx syn
fx eqy --setup --force
fx eqy
fx signoff --setup --force
fx sdf
fx sta
fx power_estimate
fx compile_post_syn --force
fx sim_post_syn --force --set GLS_BACKEND=sv --set TIMING_MODE=typ
fx power_analysis_all
fx fusion_analysis_all

# Physical branch
fx pnr --setup --force --set ORS=/path/to/OpenROAD-flow-scripts/flow

fx signoff_post_pnr --setup --force
fx sdf_post_pnr
fx sta_post_pnr
```

## 18. Change-impact recipes

### 18.1 CSR-only change

```bash
# edit data/<top>*.hjson
fx reg doc regmap_py --force
fx top_from_core flist --force
fx lint_suite
fx cdc_rdc --setup --force
fx cdc_rdc
fx tests_gen --force
fx tb cocotb --setup --force
fx regression
fx formal_csr --setup --force
fx formal
```

Then regenerate/rerun technology-dependent setup from synthesis onward.

### 18.2 RTL behavior change

```bash
# edit RTL/model/tests/properties as required by intended behavior
fx flist --force
fx lint_suite
fx cdc_rdc --setup --force
fx cdc_rdc
fx tests_gen --force
fx tb cocotb --setup --force
fx regression
fx formal_prove formal_cover --setup --force
fx formal
```

Then rerun synthesis, equivalence, and downstream sign-off.

### 18.3 Port change

```bash
fx top_from_core flist --force
fx lint_suite
# review constraints/<TOP>.sdc
fx cdc_rdc --setup --force
fx cdc_rdc
```

Regenerate TB/formal/synthesis setup that consumes the changed interface.

### 18.4 Clock/reset topology change

```bash
fx settings N_CLOCKS=<n> CLOCK_DOMAINS=<domains> CLOCK_RELATIONSHIPS=<relations>
fx top_from_core flist --force
fx lint_suite
fx sdc --setup --force
# reapply/review authored constraints/<TOP>.sdc intent
fx cdc_rdc --setup --force
fx cdc_rdc
```

Then regenerate every clock/reset-aware DV/formal/synthesis/sign-off setup.

### 18.5 Timing-only change

Edit:

```text
constraints/<TOP>.sdc
```

Then regenerate the setup stages that consume the changed facts. Typical examples:

```bash
fx cdc_rdc --setup --force        # when clock relationships changed
fx tb cocotb --setup --force
fx syn --setup --force
fx signoff --setup --force
```

Do not regenerate the SDC from bootstrap settings for a timing-only edit.

### 18.6 PDK change

```bash
fx pdk use <pdk>
fx syn --setup --force
fx syn
fx eqy --setup --force
fx eqy
fx signoff --setup --force
...
```

Common design/DV/SDC state is preserved.

## 19. Debugging a failed target

First use the artifact-oriented debug mode when supported:

```bash
fx <target> --debug
```

It reads existing artifacts without rerunning the target.

Supported analysis families include STA, power, fusion, and GLS. Save the filtered output with:

```bash
fx <target> --debug -o <file-or-directory>
```

Other useful diagnostics:

```bash
fx <target> --live
fx <target> --dry-run --script
fx <target> --info
```

For EQY use `fx eqy_debug` because partition-level formal diagnosis has its own structure.

### 19.1 Debugging rule

Read evidence in this order:

1. compact analysis JSON / `--debug` summary;
2. canonical human report;
3. scenario-local detailed report;
4. raw tool log/script;
5. generated intermediate only when required to identify the producer bug.

This avoids searching huge logs before the analysis summary has already narrowed the problem.

## 20. Provenance and intentional generated-file experiments

Generated setup stages are content-hashed. A consumer can run only when the setup is:

```text
CLEAN
VALIDATED_OVERRIDE
```

Typical recovery:

```text
MODIFIED
  → restore bytes, validate exact override, or regenerate

STALE
  → regenerate setup with current source/config lineage

INVALID
  → repair missing/inconsistent inputs, then regenerate
```

For an intentional experiment:

```bash
fx syn --setup
# manually edit generated setup
fx validate_override --set STAGE=syn --setup
fx syn
```

Do not use `validate_override` to accept stale source/config lineage.

## 21. What “complete” means in FlexSoC

Completeness does not mean generating every possible report. It means that each important engineering question has one clear evidence path:

```text
structure        lint + CDC/RDC
behavior         functional regression + coverage
invariants       formal
mapping          synthesis
preservation     equivalence
timing           STA
power            estimate + activity analysis
implementation   PnR + extracted artifacts
physical         physical_signoff
traceability     manifest + provenance
cross-flow QoR   metrics.json
human closure    fx check
```

Prefer one complete artifact over many overlapping files. Prefer one reusable primitive over a semantic wrapper that adds no hardware behavior. Prefer one normalized metrics snapshot over a future UI that reparses raw EDA text.
